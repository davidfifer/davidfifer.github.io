Distributed Tracing Demo

Overview

distributed-tracing-demo is a lightweight FastAPI microservice system designed to showcase real-world distributed tracing, latency propagation, and error propagation across service boundaries. It provides a clean, containerized environment where three cooperating services—frontend, API, and worker—emit spans through OpenTelemetry and visualize them in Jaeger. The project emphasizes clarity, reliability, and hands-on observability, making it ideal for engineers exploring OpenTelemetry, microservice debugging patterns, or modern tracing workflows.

With built‑in chaos mode, structured span attributes, and both auto‑instrumented and manually‑created spans, the demo highlights how trace context flows through a multi‑hop request and how failures ripple through upstream services. Its Docker‑based orchestration, simple architecture, and well‑documented behavior make it a practical teaching tool, a foundation for experimentation, and a reference implementation for teams adopting distributed tracing in production systems.

Architecture & Design

distributed-tracing-demo is built around a deliberately simple but expressive microservice architecture that highlights how trace context moves through a real system. The project consists of three FastAPI services—frontend, API, and worker—each running in its own container and communicating over lightweight HTTP calls. This separation mirrors production-style service boundaries and makes it easy to observe how latency, failures, and retries propagate across hops.

Each service is instrumented with OpenTelemetry using a mix of automatic and manual span creation. Core behaviors such as request handling, downstream calls, background work, and chaos-mode fault injection are isolated into clear modules, ensuring that tracing logic never pollutes business logic. The design emphasizes readability, minimal coupling, and predictable flow, making it straightforward to extend with new endpoints, additional spans, custom attributes, or alternative exporters.

Docker Compose orchestrates the entire system, providing a reproducible environment where Jaeger, the services, and supporting components start as a unified stack. This containerized layout ensures consistent behavior across machines and simplifies experimentation with observability patterns, failure scenarios, and multi-service debugging techniques.

  • Frontend Service: Handles incoming user requests, generates initial spans, and forwards calls to the API service while preserving trace context. It provides a clean entry point for observing how upstream latency and errors propagate through the system.
  • API Service: Acts as the central coordinator, performing downstream calls to the worker service, enriching spans with custom attributes, and demonstrating both auto‑instrumented and manual tracing patterns.
  • Worker Service: Simulates background or computational work, introduces optional chaos‑mode delays and failures, and showcases how trace context flows into deeper layers of a distributed system.
  • OpenTelemetry Instrumentation: Provides end‑to‑end distributed tracing with consistent span structure, context propagation, custom attributes, and clear visibility into multi‑hop request flows.
  • Chaos Mode: Injects randomized latency, errors, and jitter to demonstrate how failures ripple through upstream services and how traces reveal bottlenecks and instability.
  • Structured Error Handling: Produces predictable error responses and trace annotations, making it easy to diagnose failure points and understand how exceptions affect the overall trace.
  • Jaeger Integration: Offers real‑time visualization of spans, timing, and service interactions, enabling intuitive exploration of request lifecycles and debugging patterns.
  • Dockerized Runtime: Uses Docker Compose to orchestrate all services and Jaeger, ensuring reproducible environments, simple onboarding, and consistent behavior across machines.

Key Features

  • End‑to‑End Tracing: Captures every request as a trace that flows through the frontend, API, and worker services, making it easy to visualize latency, bottlenecks, and multi‑hop behavior.
  • Multi‑Service Request Flow: Demonstrates how distributed systems handle upstream and downstream calls, including context propagation, retries, and structured span attributes.
  • Chaos Mode Simulation: Injects randomized latency, jitter, and controlled failures to mimic real‑world instability and reveal how errors ripple through dependent services.
  • Structured Span Data: Enriches traces with custom attributes such as timing markers, worker behavior flags, and chaos indicators, enabling deeper debugging and performance analysis.
  • Consistent Error Surfacing: Produces predictable error responses and trace annotations that help correlate failures with their originating spans and upstream impact.
  • Jaeger Visualization: Provides real‑time span inspection, service dependency graphs, and timing breakdowns, giving developers an intuitive view of distributed workflows.
  • Containerized Deployment: Runs all services and Jaeger in a reproducible Docker Compose environment, ensuring consistent behavior across machines and simplifying onboarding.

Usage Examples

Trigger a Basic Frontend Request

curl -X GET http://localhost:8000/start

Trigger a Full Trace (Frontend → API → Worker)

curl -X GET http://localhost:8000/start

Enable Chaos Mode (Random Latency & Errors)

curl -X GET "http://localhost:8000/start?chaos=true"

Send Multiple Chaos Requests

for i in {1..10}; do \
    curl -s "http://localhost:8000/start?chaos=true"; \
    echo; \
    done

Call API Service Directly

curl -X GET "http://localhost:8001/process?chaos=false"

Call Worker Service Directly

curl -X GET "http://localhost:8002/work?chaos=true"

View Traces in Jaeger

http://localhost:16686

Configuration

distributed‑tracing-demo uses simple, service‑specific config.py files and environment variables to control tracing behavior, exporter settings, chaos‑mode parameters, and runtime options. Each service (frontend, API, worker) loads its own configuration at startup, allowing developers to adjust latency injection, error simulation, span attributes, and OpenTelemetry exporters without modifying application code.

The project also supports Docker‑based configuration through docker-compose.yaml, enabling consistent setup of Jaeger, service ports, environment flags, and development overrides. This flexible configuration model makes it easy to experiment with tracing flows, toggle chaos mode, or integrate alternative observability backends.

Engineering Challenges & Solutions

  • Trace Context Propagation: Ensuring consistent trace context across three independent FastAPI services required careful coordination of headers, middleware, and OpenTelemetry instrumentation. The solution was a unified propagation strategy that guarantees every hop—frontend, API, worker—contributes clean, connected spans.
  • Multi‑Service Latency Visibility: Distributed systems often hide where latency originates. The demo solves this by enriching spans with custom timing attributes and structuring traces so developers can immediately see which service introduced delay and how it affected upstream calls.
  • Chaos‑Mode Stability: Injecting randomized failures and jitter without destabilizing the entire stack was a challenge. The solution was isolating chaos logic inside the worker service and annotating spans with chaos indicators, allowing controlled experimentation without breaking the environment.
  • Consistent Error Surfacing: Errors in distributed systems often appear disconnected or ambiguous. The project addresses this by producing predictable error responses and attaching structured exception metadata to spans, making failure origins immediately visible in Jaeger.
  • Observability Extensibility: Supporting both auto‑instrumented and manual spans while keeping the codebase clean required a modular tracing design. Each service isolates tracing concerns, making it easy to add new endpoints, exporters, or span attributes without disrupting existing flows.
  • Reproducible Deployment: Running multiple services plus Jaeger consistently across machines can be error‑prone. Docker Compose solves this by orchestrating the entire stack with predictable ports, environment variables, and startup order, eliminating environment drift.
